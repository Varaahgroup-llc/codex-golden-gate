# Security model

The entry UI is trusted code delivered by the installed MCP server. It uses Web Crypto to encrypt a JSON payload with a fresh AES-256-GCM key and wraps that key using the form's ephemeral RSA-2048 OAEP/SHA-256 key. AES additional authenticated data binds the payload to the request ID. The payload includes a random 256-bit capability and explicit consent. The server stores the immutable destination and identity; neither is accepted from the submission payload.

The AI-visible open/status results contain metadata and receipts. The submission tool accepts ciphertext, wrapped key and IV; it has no plaintext secret input. The capability and public key are in widget-only result `_meta`. App-only tool visibility is a host routing hint, not the security boundary: authenticated encryption, capability validation, expiry, and single-use state are enforced on the server.

The UI makes no external network requests, embeds no remote assets, and does not call widget-state, model-context or follow-up-message APIs with the value. It clears form inputs after encryption and on cancellation, expiry, completion and page hide. The server clears key material after submission/expiry/cancellation and buffers where practical. JavaScript strings, process memory, swap and garbage collection cannot provide guaranteed secure erasure. No guarantee is made against a compromised host, OS, browser, extension, CLI installation, or privileged local process.

The plugin runs locally under the user's operating-system account. The form and runtime necessarily see the plaintext. Ciphertext may be retained in host tool history; private decryption keys exist only in the server process and are not written to disk. Do not enable host/provider debugging or capture the form, local process memory, or secret-bearing stdin. Encryption does not make it safe to use an untrusted host.

Dotenv writes are plaintext by design. The adapter resolves the parent path before displaying the target, refuses a symlink target and unsupported syntax, checks Git rules, uses a same-directory exclusive lock, writes a `0600` temporary file, checks for concurrent changes and renames atomically. The lock coordinates this adapter; an unrelated process or malicious directory writer can still race it. Use directories controlled by the current user. Atomic-write temporary files can remain after abrupt process/OS crashes and need private handling. Do not promise forensic deletion.

Cloud adapters run trusted CLIs using argument arrays and pipe input; no shell interpolation or secret-value flags are used. Existing CLI auth is reused. Identity and subscription are reviewed in the form and identity is rechecked before saving. Write stdout/stderr is suppressed. Provider/transport retries may occur inside a CLI; the plugin itself does not automatically retry an unacknowledged write. AWS uses a unique idempotency token per submission. A cloud failure is conservatively marked uncertain.

The initial implementation has automated tests, not an independent security audit or complete cross-platform/host certification. Report vulnerabilities privately through [GitHub private vulnerability reporting](https://github.com/Varaahgroup-llc/codex-golden-gate/security/advisories/new). Do not include a real secret in a public issue. If private reporting is temporarily unavailable, contact a repository maintainer to arrange a private channel before sharing details.
